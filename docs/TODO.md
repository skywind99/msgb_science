### AI 키·호출 설계 (확정)

**이전의 환경변수 `GEMINI_API_KEY` 방식은 폐기했다.** 공급자가 둘로 늘고 관리자가
화면에서 키를 갈아끼울 수 있어야 해서 DB 보관으로 바꿨다.

**키의 주인은 사람이 아니라 사이트다.** 누가 AI 버튼을 눌러도 서버가 같은 키 세트
(Groq, Gemini)를 쓴다. 교사별 키는 없다.

저장
- 설정 테이블 **한 행**. 공급자별 키를 **AES-256-GCM** 으로 암호화해 저장하고
  복호화는 서버에서만 한다.
- 비밀값은 환경변수 **`AI_KEY_SECRET`**.
- **키가 로그·응답·에러 메시지에 나오지 않게 한다.**

권한
- 키 등록·교체·삭제는 **`role === "admin"` 만** (`InviteManager` 와 같은 조건).
  관리자가 여러 명이어도 마지막 저장이 유효하다.
- 사용은 로그인한 교사 전원.

라우트
- `GET /api/ai/status` — `{groq, gemini}` **boolean 만** 반환. 키 값은 절대 반환하지 않는다.
- `PUT` · `DELETE /api/admin/ai-keys` — admin 만.
- `POST /api/ai/fill` — `{imageUrl}` 또는 `{text}`.
  응답은 JSON 스키마로 강제하고 **서버에서 zod 로 다시 검증한다.**

공급자
- 두 모드 모두 **Groq 우선, 실패 시 Gemini 폴백.**
- Groq 비전 모델은 프리뷰일 수 있다. **공식 문서(Images and Vision)에서 현재
  모델명을 확인**해 상수 한 곳에 두고 Gemini 폴백을 유지한다.
- 이미지 모드 우선순위는 **상수로 바꿀 수 있게** 하고, 실제 한국어 포스터 3~4장으로
  두 쪽 결과를 비교할 수 있게 한다.
- 이미지는 **Supabase 공개 URL 을 그대로 전달하는 방식을 우선 검토**한다
  (도메인 허용은 유지). base64 는 4MB 제한을 고려할 것.

오류는 원인별로 구분한다 (6종)
1. **키 미등록** — 컬럼이 `null`
2. **키 거부됨 (401·403)** — 공급자가 키를 거절. 폐기·오타·권한 문제
3. **한도 초과 (429)**
4. **모델 종료·없음 (404)**
5. **응답 형식 오류** — JSON 파싱 실패 또는 zod 재검증 실패
6. **이미지 주소·용량 거부** — 허용 도메인 아님 / 상한 초과

   `키 미등록` 과 `키 거부됨` 은 화면 문구를 나눈다.
   `AI_KEY_SECRET` 이 달라져 복호화가 안 되는 `키 읽기 실패` 는 또 다른 경우다.

   | 내부 상태 | 교사 화면 | AI 설정 팝업(admin) |
   |---|---|---|
   | 키 미등록 | "관리자가 AI를 설정하지 않았어요" | "키가 등록되지 않았습니다" |
   | 키 거부됨 | "AI 키가 거부됐어요. 관리자에게 알려 주세요" | "키를 다시 확인하세요" |
   | 키 읽기 실패 | "AI 키를 읽을 수 없습니다. 관리자에게 알려 주세요" | "키를 다시 등록해야 합니다" |

모델명
- 공급자별 상수 **한 곳**. **종료 임박 모델은 고르지 않는다.**

제한
- `imageUrl` 은 우리 Supabase 도메인만, 용량 상한
- `{text}` 는 8000자
- **교사별 시간당 20회** (`rateLimit.ts` 재사용)
- 요청 내용 로그 금지

화면
- **admin 에게만** 상단 메뉴에 "AI 설정" — Groq 키·Gemini 키 각각 입력·저장·삭제·상태.
- 교사 화면에는 **상태만.**
- 개인정보 안내 문구는 공급자 약관 확인 후 사용자가 확정한다. **자리만 만들어 둘 것.**

## 방향

기존 공지 게시판을 **활동 신청까지 되는 하이브리드 게시판**으로 확장한다.

확정된 설계 원칙
- **학생 계정을 만들지 않는다.** 신청은 학년·반·번호·이름 + 학생이 정하는 확인 비밀번호.
  (2026-07-27: 6자리 랜덤 코드에서 바뀜. 외우기 어렵다는 이유.
  랜덤보다 약해지므로 `shared/studentSecret.ts` 의 약한 값 거부와
  조회 요청 제한이 **함께** 있어야 한다.)
- **교사만 로그인한다.** Supabase Auth 사용, 자율 가입 없이 초대 링크로만 계정 생성.
  로그인은 이메일이 아니라 아이디다 (2026-07-28). `shared/teacherId.ts` 참고.
  메일을 못 받으므로 관리자용 비밀번호 재설정이 유일한 복구 수단이다.
- **개인정보는 최소한만, 짧게.** 연락처·이메일·생년월일 수집 안 함 (교사도 이메일을 받지 않는다).
  활동 종료 30일 후 신청 기록 자동 삭제.
- **교사가 배울 게 없어야 한다.** 글쓰기 화면에 "신청 받기" 토글 하나가 추가되는 수준.

검토 후 제외한 선택지
- 나이스 계정 연동 — 나이스가 외부에 여는 것은 학교 기본정보·급식·학사일정 등 데이터 조회용 Open API이고, 신원 확인용 SSO는 제공되지 않음. 급식/학사일정 표시 용도로는 나중에 활용 가능.
- 구글 워크스페이스 로그인 — 학교 도메인 계정이 없어 해당 없음.
