## [Unreleased]

### 수정
- **게시물 이미지가 아래쪽이 잘려 보이던 문제 수정.** 대표 이미지와 본문 이미지를
  원본 비율 그대로 전체 표시한다. 세로로 긴 가정통신문·포스터도 잘리지 않는다.
  글쓰기·팝업 편집 화면의 미리보기도 잘리지 않게 바꿨다.
  (목록 썸네일과 팝업 표시는 레이아웃 유지를 위해 기존 방식대로 채워 자른다.)
- 관리자 이미지 업로드가 항상 실패하던 문제 수정. `@supabase/supabase-js` 가
  Node 20 에서 클라이언트 생성 단계부터 예외를 던지던 것이 원인.
  Storage 사용량 조회에도 같은 문제가 있어 함께 고쳤다.
- 업로드 실패 메시지가 원인과 무관하게 항상 "SUPABASE 환경변수를 확인하세요" 로
  나오던 문제 수정. 이제 환경변수 누락과 실제 업로드 실패가 구분된다.

### 추가
- **학생 온라인 신청** — 신청을 받는 활동 글에 "신청하기" 버튼이 생겼다.
  계정 없이 학년·반·번호·이름만 넣으면 되고, 완료하면 **6자리 확인코드**가 나온다.
  이 번호는 그 화면에서 한 번만 보여준다. 서버는 해시만 저장하므로 다시 알려줄 수 없다.
  - 정원이 차면 대기자로 등록된다(교사가 껐으면 신청이 막힌다).
  - 앞 순번이 취소하면 대기자 한 명이 자동으로 신청 확정이 된다.
  - 확인코드로 본인 신청을 조회하고 취소할 수 있다. 취소하면 기록이 지워진다.
  - 신청 비밀번호가 걸린 활동은 비밀번호를 함께 입력해야 한다.
  - **아직 배포하지 않았다.** 교사용 명단 화면(4단계)이 나온 뒤 함께 연다.
- 활동 상세와 일정 화면에 **남은 자리**가 표시된다 (`12 / 24명 · 12자리 남음`).
  신청자 수만 보이고 누가 신청했는지는 나오지 않는다.
- **활동 게시물** — 글쓰기 화면 맨 아래에 "신청 받기" 토글이 생겼다. 켜면 활동 일시,
  장소, 정원, 신청 기간, 준비물, 신청 비밀번호를 입력할 수 있다.
  끄면 지금까지와 똑같은 공지글이고 기존 게시물은 손댈 필요가 없다.
  게시물 수정 창에서도 같은 항목을 고칠 수 있다.
- 활동 글 상세 페이지 상단에 **활동 정보 요약**이 표시된다.
  일시·장소·정원·신청 마감과 "신청 받는 중 / 신청 예정 / 마감 / 종료" 상태를 보여준다.
- 홈에 **신청 마감 임박 활동**이 최대 3건 나타난다. 마감이 빠른 순이고,
  신청 받는 활동이 없으면 영역 자체가 보이지 않는다.
- **활동 일정 화면** (`/schedule`) — 카테고리에 흩어진 활동을 날짜순으로 모아 본다.
  상단 메뉴에 "활동 일정"이 추가됐다. 지난 활동은 접혀 있고 눌러서 펼친다.
- 목록 카드에 활동 배지와 활동 일시·장소가 표시된다.
- **교사 계정 로그인** — 로그인 창에 이메일 로그인이 추가됐다. 기존 관리자 비밀번호도
  그대로 쓸 수 있고, 창 아래 링크로 전환한다. 교사 계정으로 들어오면 이름이 표시된다.
  (계정 발급 준비가 끝나기 전까지는 기존 방식만 동작한다.)
- `docs/` 디렉터리 신설 — TODO, UPDATE, DEVLOG 문서화 체계 도입
- `.env.example` 추가. 서버가 쓰는 값은 `DATABASE_URL`, `SUPABASE_URL`,
  `SUPABASE_SERVICE_KEY`, `ADMIN_PASSWORD` 네 개이고, 교사 로그인을 위해
  브라우저용 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 두 개가 더 필요하다.
- 활동 신청 게시판용 DB 스키마 (`profiles`, `invites`, `applications`).
  아직 이 테이블을 쓰는 화면·API 가 없어 동작 변화는 없다.

### 보안
- **게시물 API 응답에서 신청 비밀번호 해시를 제거했다.** 게시물 조회는 로그인 없이
  누구나 할 수 있어서, 해시가 그대로 실려 나가면 긁어 모아 오프라인에서 대입할 수 있었다.
  이제 "비밀번호가 걸려 있는지" 여부만 내려간다.
- **확인코드 조회에 요청 제한을 걸었다.** 6자리 숫자라 제한이 없으면 전부 대입해서
  명단을 긁어낼 수 있다. 같은 학생 기록을 연속으로 5번 틀리면 잠시 조회가 막히고,
  맞히면 즉시 풀린다. 정상적으로 조회하는 학생은 영향을 받지 않는다.
- 신청자 명단은 어떤 공개 API 로도 나가지 않는다. 신청자 수·남은 자리 같은 집계만 내려간다.

### 변경
- 실행 환경을 Node 22 이상으로 지정 (`engines.node`). 배포는 24.x 로 동작한다.
- `npm run dev` 가 Windows PowerShell 에서 동작하도록 수정.
- `.env` 파일을 자동으로 읽는다. 이전에는 셸에서 직접 지정해야 했다.

### 운영 메모
- **배포 전에 `npm run db:push` 로 `rate_limits` 테이블을 만들어야 한다.**
  요청 제한 카운터를 담는 새 테이블이다. 없으면 신청·조회가 전부 막힌다
  (요청 제한이 동작하지 않을 때는 열지 않고 막도록 만들었다).
  기존 테이블은 바뀌지 않으므로 데이터에는 영향이 없다.
- Vercel 환경변수를 바꾼 뒤에는 **재배포를 해야 적용된다.** 기존 배포에는 반영되지 않는다.
  같은 이유로 로컬에서 `.env` 를 고쳤으면 dev 서버를 재시작해야 한다.
- 관리자 비밀번호는 환경마다 별개다. 로컬은 `.env`, 배포는 Vercel 환경변수를 본다.
  서로 달라도 문제없다.
- 교사 로그인을 배포에서 쓰려면 Vercel 에 `VITE_SUPABASE_URL`,
  `VITE_SUPABASE_ANON_KEY` 를 추가해야 한다. 없으면 로그인 창에 이메일 항목이
  나타나지 않고 기존 방식만 동작한다.
- 업로드 가능한 이미지 크기는 약 4MB 다. Vercel 함수의 요청 본문 한계가 4.5MB 라
  그보다 큰 사진은 서버에 닿지 못한다.
