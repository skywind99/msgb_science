미사강변고등학교 과학중점고 사이트를 **무엇을, 어떤 순서로, 왜 그렇게 만들었는지**
처음부터 끝까지 적은 글이다.

읽는 사람으로 **이 사이트를 넘겨받는 사람**과 **비슷한 학교 사이트를 처음 만드는
사람**을 생각했다. 코드는 읽을 줄 알지만 이 프로젝트는 모른다고 보고 썼다.

- 지금 코드가 어떻게 생겼는지는 `CLAUDE.md`
- 그때그때 무엇을 왜 정했는지는 `docs/DEVLOG.md`
- 사용자 눈에 무엇이 달라졌는지는 `docs/UPDATE.md`
- 남은 일과 보류한 것은 `docs/TODO.md`
- 사고가 났을 때는 `docs/RECOVERY.md`

이 글은 그 넷을 **시간 순서로 꿰어** 읽는 길잡이다. 세부는 각 문서로 넘긴다.

## 1. 기반 (2026-03-26 ~ 04-14)

### 1-1. 무엇부터 세웠나

첫 커밋은 2026-03-26 이다. React SPA 하나를 Express 가 서빙하는 평범한 구조로
시작했고, 2026-04-13 에 **Vercel 서버리스로 옮기면서 구조가 한 번 틀어졌다.**

```
client/     React SPA (Vite)
server/     Express 라우트
shared/     스키마와 API 계약 (양쪽이 같이 쓴다)
api/        Vercel 진입점
script/     빌드 스크립트
```

`shared/` 를 둔 것이 뒤에서 계속 이득이 됐다. 스키마(`schema.ts`)와 API 계약
(`routes.ts`)을 화면과 서버가 **같은 파일로** 보기 때문에, 한쪽만 고쳐서 어긋나는
일이 구조적으로 줄었다. 나중에 화면이 서버와 **같은 규칙으로 미리 검사**하는
패턴도 여기서 나왔다.

### 1-2. Vercel 로 옮기며 걸린 것 — 하루에 커밋 네 개

```
50bbe48 add vercel config
87502ca fix module paths for vercel
83a4740 fix: bundle api with esbuild
bdb8e93 fix: esm import extensions for vercel
```

같은 날 네 번 고쳤다. 서버리스는 **로컬에서 되는 것이 배포에서 안 된다.**

- 모듈 경로가 다르다
- API 를 **esbuild 로 번들해야** 한다 (`script/build-api.ts`)
- ESM import 에 **확장자(`.js`)를 붙여야** 한다 — TypeScript 소스에 `.js` 를 쓰는
  어색한 모양이 여기서 왔다. 지금도 그렇게 돼 있다

> **처음 만드는 사람에게:** 배포 대상을 먼저 정하고 거기 맞춰 시작하라. 다 만들고
> 옮기면 위 네 가지를 한꺼번에 맞아야 한다.

### 1-3. 관리자 로그인 (첫 번째 버전 — 나중에 통째로 버린다)

### 2-2. 이미지 업로드와 미러링 (06-23)

Supabase Storage 에 올린다. 외부 이미지는 **미러링**해서 우리 쪽에 복사한다 —
남의 서버 이미지를 직접 걸면 그쪽이 지우는 순간 깨진다.

> 이때 심은 버그가 넉 달 뒤에 터진다. 파일명을 URL 의 base64 **앞부분만 잘라서**
> 만들었더니 기사 URL 들이 **같은 파일명으로 충돌**했다. 뉴스 이미지가 전부 같은
> 그림으로 보였다. 2026-10-18 에 sha256 전체 해시로 바꿔 고쳤다(5-2).

### 2-3. 팝업, 유튜브 임베드 (06-23)

같은 날 팝업 표시/관리와 유튜브 임베드를 넣었다. 팝업은 이후 **세 번 더
손본다**(링크 동작, 중복 방지, 이미지 크기). 작아 보이는 기능인데 손이 많이 갔다.

### 2-4. keep-alive — 무료 DB 는 쉬면 멈춘다

```

```

Supabase 무료 플랜은 **일정 기간 요청이 없으면 프로젝트를 재운다.** 학교 사이트는

커밋 로그가 `chore: keep-alive` 로 도배되는 건 이 때문이다. 이력을 읽을 때는

## 3. 설계 결정일 (2026-07-25)

**이 프로젝트에서 가장 중요한 하루다.** 설계를 정하고 **문서 체계를 세웠다.**

```
980b649 docs: CLAUDE.md 및 작업 문서 추가
af81286 feat: 하이브리드 게시판 스키마 (교사 계정 · 초대 · 활동 신청)
```

`CLAUDE.md` 와 `docs/` 네 문서가 이날 생겼다. 그 전 넉 달치 커밋 메시지가
`Update routes.ts` 같은 식이었던 것과 비교하면 이후가 확연히 다르다.
`docs/DEVLOG.md` 의 "활동 신청 게시판 설계 결정" 항목이 그날 기록이다.

무엇을 만들지보다 **무엇을 안 만들지**를 먼저 정했다.

### 3-1. 학생 계정을 만들지 않는다

가장 큰 결정이다. 신청은 **무계정 + 학년·반·번호·이름 + 학생이 정하는 확인
비밀번호**로 받는다.

**왜 안 만드나.** 학생 계정을 만들면 그 뒤가 전부 담당 교사 몫이 된다.

- 비밀번호 잊었다는 문의
- 졸업생·전학생 계정 정리
- 개인정보 보관 책임

본인 확인이 느슨해지는 건 알고 받아들였다. 대신 셋으로 보완한다.

- `(post_id, grade, class_no, student_no)` **유니크 제약**으로 1인 1건
- 교사가 명단을 **최종 확정**
- 활동별 **신청 비밀번호**(선택)

> **비슷한 걸 만드는 사람에게:** 학교 사이트에서 계정을 만들면 유지보수 비용이
> 전부 선생님에게 간다. 계정 없이 되는지부터 따져 보라.

### 3-2. 교사 인증은 Supabase Auth 를 쓴다

JWT 를 직접 구현하지 않는다. 교사 여러 명 + 역할 구분 + 초대 흐름이 필요한데
전부 Supabase Auth 에 있다. **자율 가입은 열지 않는다** — 관리자가 발급한 초대
링크로만 계정이 생긴다. 역할은 `admin`(전체)과 `teacher`(자기 활동만) 두 단계.

### 3-3. 알림은 ICS 캘린더로 한다 — 웹푸시는 안 쓴다

iOS 는 홈 화면에 추가했을 때만 웹푸시가 동작한다. **학생 절반이 못 받는다.**
절반만 되는 알림은 없는 것보다 나쁘다 — 못 받은 쪽은 자기가 못 받은 줄 모른다.

### 3-4. 나이스 연동은 불가능하다

조사해서 **안 된다고 결론내고 적어 뒀다.** 나이스가 여는 건 학교정보·급식·학사
일정 조회용 Open API 고 SSO 는 없다. 이런 "조사해 보니 안 되더라" 를 적어 두면
다음 사람이 같은 조사를 반복하지 않는다.

## 4. 본체 만들기 (2026-07-25 ~ 07-28)

### 4-1. 인증 교체 — 병행 → 전환 → 제거

한 번에 갈아엎지 않았다.

1. **07-26** `b69a50a` — Supabase Auth 로그인을 **기존 관리자 비밀번호와 병행**해 추가
2. **07-27** `3aa9e67` — 교사 초대 링크 흐름 완성
3. **07-28** `cc536be` — 로그인을 **이메일에서 아이디로**
4. **07-28** `5e1b788` — `x-admin-password` **제거** (되돌리지 않는다)

**왜 `x-admin-password` 를 버렸나.** 평문 비밀번호를 `localStorage` 에 두고 매
요청에 실어 보내는 구조였다.

- XSS 한 번이면 샌다
- 만료가 없다
- **모두가 같은 값을 써서 누가 무엇을 했는지 알 수 없다**
- 게시물 `authorId` 가 비어서 담당 교사가 자기 활동 명단을 못 보던 문제도
  여기서 나왔다

**아이디 로그인의 대가.** Supabase Auth 가 이메일을 요구하므로 `kim` →
`kim@msgb.invalid` 로 바꿔 넘긴다(`shared/teacherId.ts`). `.invalid` 는 RFC 2606
예약 TLD 라 누구도 소유할 수 없다.

대신 **메일을 받을 수 없어 교사가 스스로 비밀번호를 재설정하지 못한다.** 그래서
관리자용 재설정(`POST /api/teachers/:id/reset-password`)이 **유일한 복구 수단**이다.
이걸 지우면 비밀번호를 잊은 교사가 영구히 못 들어온다. `docs/RECOVERY.md` 참고.

`toLoginEmail` 은 입력에 `@` 가 있으면 그대로 쓴다. 아이디 방식 이전에 실제
이메일로 만든 계정이 잠기지 않게 하는 예외다.

### 4-3. 확인 코드 → 학생 지정 비밀번호 (07-27)

원래는 서버가 **6자리 랜덤 코드**를 발급했다. 학생이 외우기 어렵다고 해서
**학생이 직접 정하는 비밀번호**로 바꿨다(`656af3d`).

랜덤보다 약해지므로 둘을 **함께** 뒀다.

- `shared/studentSecret.ts` — 추측하기 쉬운 값 거부
- `server/rateLimit.ts` 의 `lookupPerStudent` — 실패 5회 / 10분

**장시간 잠금은 두지 않기로 했다.** 학교에서 하루 잠기면 학생이 교사를 찾아가게
되고, 그게 이 설계로 피하려던 부담이다.

> 이 "둘이 함께" 라는 전제가 2026-10-18 에 **한쪽만 빠지면서** 깨진다(6-1).

### 4-4. 신청 기록 30일 자동 삭제 (07-28)

`48027c5`. 활동 종료 30일 뒤 신청 기록을 지운다(`script/cleanup.ts`).
**안 지우는 개인정보가 제일 위험하다.** 보유 기간을 코드로 강제했다.

### 4-5. 요청 제한 — DB 에 둔 이유

`server/rateLimit.ts` 를 **DB 기반**으로 만들었다. 서버리스에서는 모듈 전역
변수가 **인스턴스마다 따로 존재한다.** 메모리 카운터를 쓰면 인스턴스가 늘어난
만큼 제한이 느슨해진다.

(같은 이유로 뉴스 캐시가 지금도 무효 상태다. 전역 변수에 캐시해 뒀는데 인스턴스
마다 따로라 거의 안 맞는다. 알려진 문제로 적어 뒀다.)

### 교훈 — `userAgent` 로 기능을 **감추지 마라**

- 판별이 빗나가면 학생은 **다른 경로를 고를 수 없다** — 막다른 길이 된다

그래서 규칙을 세웠고 `CLAUDE.md` 에 박아 뒀다.

### 9-1. 게시물 삭제 권한 (PR #4)

2. 없는 글  → 404   ← 403 보다 먼저다

없는 글에 403 을 주면 "권한이 없다" 가 곧 "그 글은 있다" 는 뜻이 된다. 라우트
안에 섞여 있으면 토큰 없이는 시험할 수 없어서 순수 함수로 뺐다.

(명단 경로는 **반대로 권한을 먼저** 본다. 거기는 학생 개인정보가 걸려 있어서

### 12-1. 비밀번호 강도 검사 제거 (PR #14) — 지금도 그대로다

"학생 비밀번호 설정을 쉽게 하고 싶다" 는 요청. 선택지 셋을 제시했고 **전부
해제**를 골랐다. 권하지 않은 쪽이었고, **권하지 않는 이유를 숫자로 적고 진행했다.**

`shared/studentSecret.ts` 에서 `COMMON`(약 60개)·연속·반복·생년월일·자기 학번
검사와 "숫자만 쓸 때 6자" 규칙을 전부 뺐다. 남은 건 **길이(4~20자)와 공백**뿐.
`1234` 도 `0000` 도 생년월일도 통과한다.

**중요한 건 어느 제한이 막느냐다.** 여기서 성립하는 공격은 한 학생을 집중해서
찍는 게 아니라 **흔한 값 하나를 전교생 번호에 한 번씩 찍는 것**이다. 그 수법은
학생당 1회라 `lookupPerStudent`(실패 5회/10분)에 **절대 안 걸린다.**
막는 건 `lookupPerIp`(실패 20회/1시간) **하나뿐**이다.

- 한 IP 가 한 시간에 찍어볼 수 있는 학생: **약 20명**
- 한 반 30명을 훑는 데: **약 1.5시간**

이 계산을 코드 주석과 `CLAUDE.md` 에 박아 뒀다. **`lookupPerIp` 를 늘리려는
사람이 먼저 읽어야 하는 숫자다.**

### 12-2. 명단을 교사 전체에게 → **당일 되돌림** (PR #15 → revert)

"교사면 신청한 학생 명단이 보이게" 요청. `canViewRoster` 를 새로 만들어 열었다.
**보는 것과 고치는 것은 나눴다** — 확정·삭제는 담당 교사·`admin` 그대로.

그리고 같은 날 **원래대로 되돌렸다.** 볼 수 있는 사람이 적을수록 안전하고,
**누가 어느 명단을 봤는지 기록할 방법이 없는 상태에서 범위를 넓힌 것**이
부담이었다.

`git revert` 로 되돌렸다. **손으로 고치지 않았다** — 권한 경로는 한 군데만
빠뜨려도 개인정보가 샌다.

### 12-3. 여기서 배운 것

**① 고지 문구는 코드와 같은 커밋에서 고친다.** 명단을 열면서
`Privacy.tsx` 의 "담당 선생님과 관리자만 볼 수 있습니다" 가 **거짓 고지**가 됐다.
같이 고쳤고, 되돌릴 때 같이 돌아갔다.

**② `UPDATE.md` 와 `DEVLOG.md` 는 다르게 적는다.** 들어갔다 나와서 사용자 관점
순변화가 없으므로 `UPDATE.md` 에서는 **뺐고**, 결정 이력이라 `DEVLOG.md` 에는
**남겼다.**

**③ 순서가 거꾸로였다.** 범위를 넓히기 전에 **조회 기록을 먼저 붙였어야** 한다.
`DEVLOG.md` 에 그렇게 적어 뒀다.

**④ main 에 들어갔다 나오면 운영에 잠깐 떠 있었다는 뜻이다.** 몇 시간 동안 모든
교사가 모든 명단을 볼 수 있었다. 기록이 없어 누가 봤는지는 확인할 수 없다.
사실대로 적었다.

### 12-4. 그때 같이 넣은 것 — 동의 상자의 "열람 범위"

신청 동의 상자에 수집 항목·이용 목적·보유 기간은 있었는데 **누가 보는지가
없었다.** 한 줄 넣었다.

```
🛡 개인정보 수집·이용 안내
  수집 항목 — 학년, 반, 번호, 이름 (선택: 남긴 말)
  이용 목적 — 활동 참가자 확인 및 명단 관리
  열람 범위 — 담당 선생님과 관리자 (다른 학생에게는 보이지 않음)
  보유 기간 — 활동 종료 후 30일 이내 삭제
  ☐ 위 내용에 동의하며 신청합니다.
```

체크 없이는 접수되지 않는다. **화면뿐 아니라 서버도 막는다**
(`agree: z.literal(true)`).

## 13. 활동 날짜로 저장이 막히던 문제 (2026-10-21, PR #19)

제보: `"종료 일시가 시작 일시보다 빠릅니다"` 로 등록이 안 되는데
**활동 신청 받기를 꺼도 풀리지 않는다.**

### 13-1. 오류 메시지는 맞았다

날짜 `2026-10-15`, 종료 날짜 `2026-10-10`. 실제로 종료가 앞선다. 문제는 그게
아니라 **그 상태가 어떻게 만들어졌고 왜 빠져나갈 수 없었는가** 였다.

### 13-2. 원인 둘

**① AI 의 종료 날짜를 그대로 믿었다.** `applyAiDates` 가 `endDate !== date` 면
여러 날 토글을 켜고 그 값을 넣었다. `endDate < date` 는 걸러지지 않는다.
AI 가 "10월 10일 신청 마감" 을 종료일로 읽은 것으로 보이고, 결과적으로 **교사가
켜지도 않은 토글 때문에 처음부터 저장할 수 없는 폼**이 만들어졌다.

**② 끄면 칸은 숨는데 값은 계속 간다.** `activityToPayload` 가 `applyEnabled` 와
무관하게 일시·신청 기간·정원을 보냈고 서버는 앞뒤를 검사했다. **보이지 않는 칸
때문에 막히고, 끄는 것으로도 빠져나갈 수 없었다** — 5장의 막다른 길과 같은 모양이다.

### 13-3. 서버가 아니라 화면에서 고쳤다

서버 스키마에서 `applyEnabled === false` 면 검사를 건너뛰게 할 수도 있었다.
그쪽은 create·update 를 한 번에 고치지만 **모순된 날짜가 그대로 DB 에 남는다.**
화면에서 안 보내는 쪽을 골랐다.

**새 글에서만** 비운다. 수정에서 같은 짓을 하면 토글을 껐다 저장하는 순간 **이미
저장돼 있던 일시·장소·정원이 지워지고 되돌릴 수 없다.** 비우는 건 **보내는
값뿐**이라 폼 상태는 그대로고, 토글을 다시 켜면 입력해 둔 값이 돌아온다.

### 13-4. 수정 화면 — 같은 길이 있지만 좁다 (고치지 않음)

점검해서 **보고만** 했다. 같은 막다른 길이 있지만 거기엔 AI 채우기가 없고,
서버가 create·update 를 같은 스키마로 검사하므로 **DB 에 모순된 날짜가 있을 수
없다.** 사용자가 손으로 넣어야만 생기고, 방금 끈 토글을 다시 켜면 고칠 수 있다.

고친다면 **값을 비우지 말고 해당 키를 빼서 PATCH 에서 제외**하는 방식이 맞다.

### 13-5. 고치다가 같이 걸린 것

오류 표시를 내리는 조건이 `date`·`startTime` 두 칸만 보고 있었다. 오류가 붙는
칸이 늘면 **고쳤는데 빨간 줄이 남는다.** 넓게 바꿨다.

> 칸이 늘어날 때 같이 늘려야 하는 조건은 **처음부터 넓게** 두는 편이 낫다.

## 14. 팝업 이미지 (2026-10-24)

제보: PC 에서 팝업 이미지가 작고 **가운데만 잘려** 보인다.

원인은 둘. 카드가 `max-w-md`(448px) 고정이고, 이미지가 `h-52`(208px) +
`object-cover` 였다. **어떤 비율이든 208px 에 맞춰 가운데만 남는다.** 세로
포스터는 글자가 통째로 사라졌다.

- 이미지는 **원본 비율 그대로**(`object-contain`), 높이 상한 `max-h-[60vh]`,
  남는 자리는 연한 회색
- **이미지가 있는 팝업만** PC 에서 `max-w-2xl`(672px). 글만 있는 팝업은 그대로
  (글 몇 줄을 672px 로 늘리면 오히려 읽기 나쁘다)
- 카드 `max-h-[90vh]` + 세로 배치. **본문만 스크롤**되고 버튼 줄은 밖에 둬서
  닫기·자세히 보기·오늘 하루 안 보기가 **항상 보인다**

**지시에 없었지만 같이 고친 것:** 닫기 버튼 배경을 진하게 했다(`black/20` →
`black/50`). 이미지를 자르지 않으면 버튼이 **연한 회색 여백 위에 올 수 있어**
흰 아이콘이 묻힌다. **이번 변경이 만든 문제라 같이 고쳤고, 보고에 적었다.**

## 16. 되풀이해 쓴 방식 — 가이드의 핵심

기능보다 이쪽이 오래 간다.

### 16-1. 큰 변경은 쪼개고, 단계마다 확인받는다

AI 입력은 12단계, TV 화면은 7커밋, 메인 보기는 PR 두 개로 나눴다.
**각 커밋이 혼자서도 빌드되게** 유지했다(한 번 어겨서 `git reset --soft` 로
되돌린 적이 있다).

### 16-2. 안 하기로 한 것을 적는다

`docs/TODO.md` 의 절반이 **보류·안 함** 항목이다.

- 일시 없는 접수형 글 — 구현하지 않는다
- 시각 없는 기간 행사 — 보류
- 나이스 연동 — 불가능하다
- 이미지 정리 도구 — 설계만

**"왜 안 하는지" 를 적어 두면 같은 논의를 반복하지 않는다.**

### 16-3. 되돌린 것도 남긴다

`.ics` inline 되돌리기, 시작 시각 기본값 넣었다 빼기, 명단 공개 되돌리기,
폐기한 AI 키 설계. **지우지 않고 "여기는 가 봤고 아니었다" 로 남겼다.**

### 16-4. 고치기 전에 측정한다

뉴스 이미지 제보 때 "그럴듯한 원인"(짝이 안 맞는다)을 고치지 않고 먼저 쟀다.
짝은 맞았고 파일명이 문제였다. **측정 안 했으면 엉뚱한 데를 고쳤다.**

"기본 모드는 안 바뀐다" 도 해시로 증명했다.

### 16-5. 막다른 길을 만들지 않는다

- 기기 판별이 빗나가도 **다른 경로를 고를 수 있어야** 한다
- 신청 받기를 끄면 **실제로 빠져나가져야** 한다
- 못 누르는 버튼은 **보이지 않게** 한다 (누르고 403 받는 것보다 낫다)
- 오류는 **어느 칸인지 짚어** 준다

### 16-6. 개인정보는 코드와 고지를 같은 커밋에서 고친다

범위를 바꾸면 `Privacy.tsx` 와 동의 상자가 **그 커밋 안에서** 따라간다.
안 그러면 거짓 고지가 된다.

### 16-7. 권한 판단은 한 곳에서만

`canManagePost` 하나. 조건식을 자리마다 적으면 어긋난다.
**화면은 소유자를 모르고**, 서버가 계산한 불리언을 받는다.

### 16-8. 순수 함수로 빼서 시험한다

`shared/` 아래 날짜 해석, 권한 판단, 뉴스 파싱, 비밀번호 규칙, 보기 모드 계산이
전부 순수 함수다. **DB 도 브라우저도 없이** 돌릴 수 있다.

시험 러너는 안 붙였다. 임시 `.ts` 스크립트를 `npx tsx` 로 돌리고 **끝나면
지운다.** 결과(통과 개수)는 커밋 메시지에 적는다.

### 16-9. 운영 DB 를 조심한다

운영 DB 하나를 사이트와 임시 스크립트가 같이 쓴다. **연결을 흘리면 사이트가 먼저
막힌다.**

- 임시 스크립트는 `new Pool({ max: 1 })`, `finally` 에서 `pool.end()`
- 한 번에 하나만 돌린다
- **평일 수업 시간(08:30~16:30 KST)에는 먼저 알린다** — 학생이 신청하는 시간대다
- `ai_settings` 는 건드리지 않는다 (실제 키가 들어 있다)

### 16-10. 문서를 네 개로 나눈다

| 문서 | 무엇 | 언제 쓰나 |
|---|---|---|
| `CLAUDE.md` | 지금 코드와 **확정된 결정** | 결정이 바뀔 때 |
| `DEVLOG.md` | 무엇을 왜, 어디서 막혔나 | **작업할 때마다** |
| `UPDATE.md` | 사용자 눈에 달라진 것 | 배포 단위로 |
| `TODO.md` | 남은 일, **보류·안 함** | 미룰 때마다 |

`CLAUDE.md` 의 **"확정된 설계 결정 — 되돌리지 말 것"** 이 특히 값을 했다.
같은 제안이 다시 올라올 때 **"이미 검토했고 이유는 이것"** 으로 끊을 수 있다.
바꿔야 할 이유가 보이면 **먼저 묻는다.**

## 17. 처음 만든다면 — 권하는 순서

1. **배포 대상을 먼저 정한다.** 서버리스면 번들·확장자·리전부터 맞춘다
2. **무엇을 안 만들지 정한다.** 계정, 알림, 외부 연동. 조사해서 안 되면 적어 둔다
3. `shared/` 에 스키마와 API 계약을 두고 **양쪽이 같이 보게** 한다
4. **인증을 먼저 닫는다.** 이 프로젝트는 마지막에 닫았고 그동안 열려 있었다
5. 개인정보를 받기 전에 **원칙을 적고 고지 페이지를 만든다.** 코드가 먼저 가면
   고지가 거짓이 된다
6. **요청 제한을 조회 API 에 건다.** 서버리스면 **DB 기반**으로
7. **보유 기간을 코드로 강제한다.** 안 지우는 개인정보가 제일 위험하다
8. 기능은 **단계로 쪼개고 단계마다 확인받는다**
9. 순수 함수로 빼고, **고치기 전에 측정한다**
10. 네 문서를 처음부터 쓴다. 두 달 쉬면 **문서가 먼저 썩는다**
